**Experimental prerelease. Nothing in it is supported on real devices.** No claim in the
[claim ledger](https://github.com/robzilla1738/moat/blob/main/docs/STATUS.md) is `supported_installed`. Every result
below comes from GitHub CI runners or unit tests, in the environment the ledger names. Release gate **G0
("truthful experimental build") is not met yet**: three Mac/web defects are still open in the ledger.

`release-manifest.md` in this release lists every claim with the commit and CI run of its last result, and whether
that result came from this exact commit.

| Asset | What it is |
| --- | --- |
| `moat-linux-x86_64-0.1.0-alpha.2.tar.gz` | `moatd`, `moat-launch`, `moatctl` (x86_64, glibc) and `moatd.service`. An archive, **not** a signed package |
| `moat-0.1.0-alpha.2-source.tar.gz` | `git archive` of the tagged commit |
| `moat-web-0.1.0-alpha.2.tar.gz` | built fleet web UI (live mode) |
| `moat-rust-*.cdx.json`, `moat-npm-*.cdx.json` | CycloneDX 1.5 SBOMs: each Rust workspace crate (x86_64 Linux target), each npm workspace. CI checks that every locked dependency appears |
| `license-report.md`, `cargo-licenses.json`, `npm-licenses.json` | dependency licence report; the copyleft gate passed |
| `release-manifest.md` / `.json` | claims, evidence and tested commits, generated from the ledger |
| `SHA256SUMS`, `SHA256SUMS.sigstore.json`, `provenance.sigstore.json` | checksums of every asset, a keyless Sigstore signature over them, and the build-provenance attestation bundle |

```sh
sha256sum --strict -c SHA256SUMS
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/robzilla1738/moat/.github/workflows/release.yml@refs/tags/v0.1.0-alpha.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
gh attestation verify moat-linux-x86_64-0.1.0-alpha.2.tar.gz --repo robzilla1738/moat
# or all of it, with negative controls:
release/recovery-drill.sh integrity <download-dir>
```

**What the signatures mean.** They say which workflow in this repository built these bytes, and from which commit.
They come from GitHub's OIDC identity, and no long-lived release key exists. **The owner policy key is separate and
was not used**: it never enters CI, and a release signature cannot authorize a policy, a grant or a trusted key. No
macOS build is included, because there is no Apple Developer ID signing or notarization yet.

## What changed since v0.1.0-alpha.1 (d5270bd), by work package

- **G0 / W01 contracts and ledger:** the status page is now a capability/evidence claim ledger checked by a test (#12). Versioned schemas, canonical digests and shared fixtures across Rust and TypeScript (#13).
- **W02 semantics:** conservative structured diff (unknown changes count as broadening), differential counterexample search, profile capability checks, collision-free backend ids (#16). Device-scoped rules compile only against the targeted devices (#27, fixes #26), and the controller does device-targeted compiles (#34).
- **W03 exact grants:** grant scope survives serialization, issuance is idempotent, and canonical and effective digests are separate (#17). The controller and signer plan exact `moat.grant.v1` grants, publish through a journal and accept delegated phone issuers (#15).
- **W04 Linux launch authority:** a contained caller cannot get a looser session through the control socket (#20).
- **W05 proxy semantics:** authorization happens before DNS, open streams end at expiry, deny, task close, isolation and daemon stop, and direct and proxied enforcement agree (#22). Isolation keeps kernel-redirected loopback flows (#37, fixes #31; deterministic check #40). A visible CONNECT host vs SNI/Host mismatch is refused, and WebSocket upgrades go through the proxy (#46).
- **W06 durable activation (Linux):** activation journal with fault injection at every step, retained rollback intent, an independent replay high-water mark, and the restart contract "stop, not adopt" (#23). Slow-disk activation and newer-schema state after an interrupted upgrade (#46). Recovery events reach the controller, web and macOS (#36).
- **W07 macOS engine (Lane B):** generation-bound evaluator, expiry-aware cache, verified restoration, live trust reload, separate app and process identity (#19). Unsigned and CI-only.
- **W08 truthful UI (Lane B):** demo and live are separated, and action states come only from evidence (#14).
- **W09 / W10 Linux ordinary apps:** measured experiment, OpenSnitch not adopted (#25). Observe-only inventory (#30) and bpftrace connect-time attribution with loss reported (#41). BPF loader decided (#49). **Enforcement for ordinary Linux apps stays unavailable.**
- **W11 installed Linux unit:** the packaged systemd unit lets workloads write their project while containment probes still fail, on an Ubuntu runner (#24). Not Omarchy.
- **W12 standalone experience (Lane B):** Apps-first app, app detail, What changed? and diagnostics in the controller, web (#28) and macOS (#29). moat-ffi compile and envelope assembly (#35). Mac standalone apply: the owner key signs the exact snapshot behind user presence (#45).
- **W13 fleet sync:** bounded spool outbox on Linux (#38). Contiguous acks with declared gaps, reconciliation, staged rollout, and offline local changes held for the owner (#42).
- **W14 learning:** bounded capture, reviewed immutable baselines, drift as new candidates, three workflow packs (#43).
- **W15 release engineering:** SECURITY.md, CODEOWNERS, licence report with a copyleft gate, release manifest from the ledger, actions pinned to commit SHAs, support matrix, naming note (#48). SBOMs, SHA256SUMS, keyless signing and provenance attestations, and the [recovery drill](https://github.com/robzilla1738/moat/blob/main/docs/recovery-drill.md) (#50). Docs show where Moat stands by gate (#58).
- **W16 DNS and Digital Kingdom:** AdGuard Home and Pi-hole v6 adapters, DNS-only presentation, and Digital Kingdom producer authority (#44).
- **§15.2 adversarial matrix:** every case is mapped to CI tests or listed as real-device-only, and the rows are checked by a test (#33).

## Known limitations

- **Not supported on any real device.** Linux results come from GitHub runners (netns lab, and an installed unit on Ubuntu), not Omarchy. The macOS content filter has never run as a signed, approved system extension.
- G0 open defects (Lane B, in the ledger): `D-MAC-CACHE-TRUST`, `D-WEB-DEMO-SUCCESS`, `D-INCIDENT-ROUTING`.
- Linux ordinary-app rules are rejected at compile, and inventory is observe-only (TCP; UDP completeness unmeasured).
- Session hostname proxy: no TLS interception. Domain fronting through an encrypted Host behind an allowed SNI is still possible, and UDP is IP-only.
- Restarting or upgrading `moatd` stops running protected sessions; they are not adopted (#55).
- `moatd.service` keeps `CAP_SYS_PTRACE` (#54).
- No fail-closed claim, no VPN-compatibility claim, no process ancestry on macOS. Phones and the TV get DNS-only coverage.
- Fleet sync, learning and DNS adapters have component evidence only. No 24-hour outage test has been done, and phone approvals have not been tried on a device.
- No signed Arch package, no notarized Mac build, and no TUF-style updater metadata.
