**Experimental prerelease. Nothing in it is supported on real devices.** No claim in the
[claim ledger](https://github.com/robzilla1738/moat/blob/main/docs/STATUS.md) is `supported_installed`. Every result
below comes from GitHub CI runners or unit tests, in the environment the ledger names. Linux has not run on Omarchy,
and the macOS content filter has never run as a signed, approved system extension.

**Release gate G0 ("truthful experimental build") is met as of this release.** Every defect from the baseline review
is closed in the ledger with a merged regression test and a cited CI run, and no claim records a failing result.
G0 means the build is honest about what it does and does not prove. It does not mean anything is supported: G1
(a signed Mac install) and every later gate are still open.

`release-manifest.md` in this release lists every claim with the commit and CI run of its last result, and whether
that result came from this exact commit.

## What changed since v0.1.0-alpha.2 (c227644)

- **G0 closed (#62).** Each remaining defect was checked against the code and tests on main. W08 (#14) had closed the web defects. W07 (#19) had closed the Mac cache, trust reload, restoration and stale-status parts. One part of `D-MAC-CACHE-TRUST` was still open: a **first canary on macOS** was accepted, and at its deadline there was nothing to roll back to, so the "trial" stayed enforced while the UI promised a rollback. Now it is refused before verification, and the refusal writes nothing, the same contract as `moatd`. The Policy screen disables the canary option until a revision is installed. The ledger, STATUS, README and ROADMAP report G0 met.
- **Notification floods (#60).** An unchanged incident notifies once. A recurrence after acknowledge or keep-blocked is visible and counted, but notifies again only if the policy revision or urgency changed. When one subject raises many incidents, you get three individual notifications, then one summary per 10-minute window. Every incident stays listed and blocked, and grouping or muting never allows anything. The adversarial-matrix row moves from gap to CI.
- **W14 review surfaces (#61).** Web and macOS screens for capture, candidate review (permission diff, gaps, unknown identity, connections that were only ever refused), owner-only accept, drift queue and pack browser with per-device unsupported cells. On the web, enforcing prepares an unsigned proposal that waits for `owner-authorize`. The Mac requires the Keychain owner key behind user presence and refuses without it. Live e2e and Swift tests are included, along with reviewed screenshots.
- **Screenshots (#47).** DNS-only device page (demo and live e2e), refreshed web and macOS captures.

## Assets and how to verify them

Same layout as alpha.2: a Linux x86_64 archive (`moatd`, `moat-launch`, `moatctl`, `moatd.service`, **not** a signed
package), source and web tarballs, CycloneDX SBOMs, the licence report, the release manifest, and `SHA256SUMS` with a
keyless Sigstore signature and build-provenance attestations.

```sh
sha256sum --strict -c SHA256SUMS
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/robzilla1738/moat/.github/workflows/release.yml@refs/tags/v0.1.0-alpha.3 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
gh attestation verify moat-linux-x86_64-0.1.0-alpha.3.tar.gz --repo robzilla1738/moat
```

These signatures say which workflow built which bytes from which commit. They are not policy authority: the owner
policy key is separate, never enters CI and was not used. No macOS build is included, because there is no Developer ID
signing or notarization yet.

## Known limitations

- **Not supported on any real device.** Linux results come from GitHub runners, not Omarchy. The macOS filter has never run signed, and the Mac fixes in this release are unit-tested on a CI runner only.
- Linux ordinary-app rules are rejected at compile, and inventory is observe-only.
- Session hostname proxy: no TLS interception. Fronting through an encrypted Host behind an allowed SNI is still possible, and UDP is IP-only.
- Restarting `moatd` stops protected sessions (#55), and `moatd.service` keeps `CAP_SYS_PTRACE` (#54).
- No fail-closed claim, no VPN-compatibility claim, no process ancestry on macOS. Phones and the TV get DNS-only coverage.
- Fleet sync, learning, notification grouping and DNS adapters have component evidence only. Alert volume and learning quality have not been measured on real use.
- No signed Arch package, no notarized Mac build, no TUF-style updater metadata.
