# Failure behavior

What each component does when something goes wrong, what is implemented, and what still needs proof on a real device.
"Implemented" means code plus an automated test, in the environment the [claim ledger](STATUS.md) names (GitHub CI
runners or unit tests). "Device proof" means it must still be observed on Robert's hardware before the UI may claim
it. **Nothing here is proven on a real device yet.** Case-by-case test names: [adversarial matrix](adversarial-matrix.md);
the Linux crash table: [linux-activation-journal.md](linux-activation-journal.md); the proxy's stream bounds:
[proxy-stream-contract.md](proxy-stream-contract.md).

| --- | --- | --- | --- | --- |
| Controller unreachable | Keep the last valid local policy; buffer a bounded backlog. | Implemented: last verified snapshot re-verified at boot and enforced; spool keeps writing under quota; the sync agent fails the round before acknowledging anything and resends later (W13, `agent-sync.test.ts`). netns "offline restart". Omarchy untested. | Implemented in MoatKit: policy state persisted under `/Library/Application Support/Moat/state`; the extension never contacts the controller. Device proof needed. | Implemented: a device silent for 10 minutes shows *Unknown*/stale whatever it last claimed (W08); "applied" only from an endpoint receipt; reconciliation shows `stale` (W13). |
| No valid policy for a protected run | Refuse to launch with an actionable reason. | Implemented: `moat-launch` exits 126 with the reason; never runs unprotected. | Not applicable: macOS has no protected sessions; session profiles are refused (compile report). | Harness launch API returns the refusal. |
| No signed policy at all (ordinary apps) | Explicit permissive observation, labelled. | Implemented: nothing is enforced; status says so. Ordinary-app inventory is `observe_only` either way (W10). | Implemented: `observation_no_policy` decisions, coverage *observed*. | Coverage *monitoring*. |
| Recognizer or ancestry uncertain | Label it; protected runs stay restrictive; ordinary apps follow the fallback profile. | Implemented: session membership comes from the cgroup, not names; the caller's identity comes from the kernel (W04). Inventory reports `identity: null` with a reason, never a guess (W10). | Implemented: ancestry reported as unavailable; rules match the socket-owning app; actual process and responsible app kept separate (W07). | Chains marked incomplete in the UI. |
| Persistence failure during activation (disk full, failed rename, slow disk) | Never report a revision as durably applied when it is not. | Implemented (W06): each step is journaled first; a failed step is rejected as `not durable` and the prior revision stays; a failure after the kernel install restores the prior table or enters `recovery_required`; a slow disk delays activation but never reorders it or outlives a trial deadline. Unit fault matrix + a real `ENOSPC` episode in CI netns (linux-endpoint 40539984069). No power-loss test on real storage. | Implemented (W07): a failed write is never reported as durable; a failed candidate keeps the running evaluator and state (`W07Tests`). Device proof needed. | A rejected or non-durable apply is a `rejected` receipt, never `applied`. |
| Crash during activation or rollback, then restart | Deterministic reconciliation. | Implemented (W06): restart reconciles from the journal to the prior or committed revision; a rollback interrupted at any step is completed; a pending trial replaced mid-apply is restored. | Restoration re-verifies stored state and refuses tampered state; with nothing verifiable it is an explicit failure, not silent enforcement (W07). | — |
| Corrupt or newer-schema state | Keep enforcing the last verified policy; make the problem visible. | Implemented: a corrupt journal is kept and reported `recovery_required`; a torn `current` reports no policy and leaves the kernel table untouched; a corrupt replay mark falls back to the journal copy; state from a newer schema is kept and refused, not reset (#46). | Tampered state refused at restoration (W07). | — |
| Filter/daemon crash or OS disables the extension | Report loss of coverage when observable. **Do not promise fail-closed.** | nftables rules stay loaded when the daemon dies (the kernel enforces them), but this is a property of nftables, not a promise. Restart writes a `restart` record; unclean shutdown is flagged. Proxied streams end when `moatd` stops (W05), so a session loses proxied egress rather than gaining direct egress. Device proof needed on Omarchy. | When the filter is disabled or stopped, the app shows *degraded*. What macOS does with flows while the extension is crashed/upgrading is **unknown until tested**; no fail-closed claim. | Stale → Unknown (above). A reported `degraded` coverage change raises a high-urgency `coverage_lost` incident. |
| Daemon restart with protected sessions running | Defined, tested behavior. | Implemented (W06): **stop, not adopt**. Earlier sessions are killed at startup and reported `session_not_adopted` (netns "W06: sessions from before the restart are stopped (not adopted)"). Decision [#55](https://github.com/robzilla1738/moat/issues/55). | Not applicable (no sessions). | Shown as "Task stopped after restart" (#36). |
| Evaluator error | Not specified; must not be silent. | n/a (rules are compiled into nftables; the session proxy evaluates with the same moat-core evaluator). | Implemented: fallback verdict (deny by default), coverage *degraded*. | — |
| Proxy resource bound reached | Refuse, never bypass. | Implemented: connection and lookup bounds refuse with a `proxy_limit` event (`exhaustion_refuses_and_reports_rather_than_bypassing`). | n/a | Shown as "Proxy limit reached" (#36). |
| Event disk full or sequence gap | Enforcement independent of logging; show the gap. | Implemented: quota → evict the oldest unacknowledged segment with an exact `gap` record (W13 outbox); tested. | Implemented: in-memory ring with overflow/restart `GapMarker`s shown in Activity/Coverage. The Mac does not yet send `spool_low_seq`/`local_change` to the controller. | Gaps shown per device; a hole becomes a gap only when the endpoint declares it (W13). |
| Malformed or unsupported policy | Reject atomically; keep the last working revision. | Implemented: verify → render → `nft -c` → one atomic `nft -f`; tested. | Implemented: verify (moat-core via FFI) before write; atomic file write; rejection shown with reason. | Signer refuses invalid changes and broadening without the owner key. |
| Replayed snapshot | Reject. | Implemented: independent, never-lowered replay high-water (W06). | Implemented; the replay high-water mark survives local rollback. | Revision states tracked separately. |
| Broad rule breaks management | Timed canary rollback and local recovery; isolation must not reopen on heartbeat loss. | Implemented: `moatd apply --trial-secs N` reverts unless `moatd recover confirm`; `recover rollback` reverts now; a failed rollback is retried every tick (`rollback-pending`) and never reported as confirmed; the first revision cannot be a trial. Countdown needs the daemon running; a trial past its deadline while stopped is reverted at the next start. Checked in CI netns and the recovery drill (release 40569608036); Omarchy untested. | Implemented: canary apply (10 min in the UI) rolls back unless confirmed; the first revision cannot be a canary (#62); local "roll back to last known good"; isolation persisted and cleared only by a typed owner confirmation. Unit-tested, never signed. | Controller rollback is a new signed revision with older content. |
| Emergency isolation + controller loss | Must stay isolated. | Implemented and tested (isolation table survives restart and new policy; ends open proxied streams, W05). | Implemented and unit-tested (survives restart, canary rollback, new policy); wording claims new connections only. Device proof needed. | — |
| DNS resolver unreachable or unsupported (W16) | Show it; never invent evidence. | — | — | Implemented: an unsupported version reads nothing; failures set health `auth_failed` / `unreachable` / `error` with exponential backoff; its clients show `unknown`, not `dns-only`; lost history is a recorded gap (`resolvers.test.ts`). ## What the UI must never do

* Show *applied* without an endpoint receipt; show *verified* without an independent observation.
* Hide a gap, a stale device, a disabled filter, a pending rollback or a required recovery behind an overall "healthy".
* Promise fail-closed behavior on any platform before the matching device proof in [STATUS.md](STATUS.md) passes.
